Decision · Foundations

Use Title-Based File Names for Knowledge Objects

Name each knowledge object file after its title (unique across the repository) and keep the immutable ID in front matter, so Obsidian wikilinks and graph labels are human-readable.

Draft knowledge. Status proposed, quality draft. Not yet reviewed or approved by a human architect.

Context

Obsidian resolves wikilinks by file name and labels graph nodes by file name. The spec example uses <a class="ref t-concept" href="../knowledge/da-con-0002.html">Information Architecture</a>-style links.

Problem

Should files be named by ID (DA-CON-0001.md) or by title (Data Architecture.md)?

Options

  1. Title-based file names, ID in front matter.
  2. ID-based file names, title in front matter, links as Data Architecture.

Evaluation Criteria

Graph readability, link readability in plain text, rename stability, uniqueness.

Trade-offs

  • Title-based: readable links and graph; renames require link updates (Obsidian does this automatically; outside Obsidian a script must).
  • ID-based: rename-stable; unreadable graph labels and raw links.

Decision

Proposed: option 1. The validator enforces title == file name, unique titles and unique IDs. IDs are immutable; titles may change via governed rename.

Consequences

  • Titles may not contain / \ : # ^ [ ] |; e.g. "ISO IEC 11179" instead of "ISO/IEC 11179" (the official form is kept as an alias).

Assumptions

  • Exports use IDs as stable keys, so external stores are unaffected by renames.

Constraints

  • File-system-safe characters only.
