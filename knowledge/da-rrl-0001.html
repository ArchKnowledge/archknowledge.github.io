Retroactive Corrections Call for Bitemporal History

If backdated corrections must be reconstructable and past states must be reproducible, recommend a bitemporal data model.

Draft knowledge. Status proposed, quality draft. Not yet reviewed or approved by a human architect.

Rule

  • IF all of:
  • history.retroactive_corrections equals True
  • history.reproducibility_required equals True
  • THEN recommend: Bitemporal Data Model
  • BECAUSE: Historical Requirements Are Explicit

Rationale

Only a model with both valid time and transaction time can answer "what did we believe at time T′ about time T?" after backdated corrections (Bitemporal Data Model).

Evidence

Common practice in regulated domains; no verified source attached yet.

Limitations

Does not weigh cost; combine with History Strategy Scoring Model Professional.
