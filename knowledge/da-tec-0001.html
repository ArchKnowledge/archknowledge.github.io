SQL Server Temporal Tables

Microsoft SQL Server / Azure SQL feature that implements system-versioned (transaction-time) tables with automatic history tables and FOR SYSTEM_TIME queries.

Draft knowledge. Status proposed, quality draft. Not yet reviewed or approved by a human architect.

Purpose

Automatic retention of prior row versions for point-in-time analysis and audit.

Capabilities

  • System-versioned tables with period columns and a linked history table.
  • Query clauses FOR SYSTEM_TIME AS OF | FROM … TO | BETWEEN … AND | CONTAINED IN | ALL.
  • History retention policies (availability depends on version/platform).

Limitations

  • Transaction time only; application-time (valid-time) periods from the SQL standard are not provided natively, so a Bitemporal Data Model needs application-maintained valid time.
  • Some schema changes require temporarily disabling system versioning.

Architecture Role

Physical implementation of the System-Versioned History Table pattern for Temporal Data Management.

Applicable Patterns

System-Versioned History Table; transaction-time half of Bitemporal Data Model.

Alternatives

Other DBMSs with system versioning; trigger-based history tables; Change Data Capture into an archive.

Integration

History tables can be exposed to analytical platforms via CDC or batch extraction.

Verification Notes

Version-specific capabilities to be verified against current vendor documentation.
