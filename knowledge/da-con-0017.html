Data Lineage

Metadata describing the origin of data and the path, transformations and dependencies through which it flows from source to consumption.

Draft knowledge. Status proposed, quality draft. Not yet reviewed or approved by a human architect.

Definition

Data Lineage is metadata describing the origin of data and the path, transformations and dependencies through which it flows from source to consumption.

Explanation

Lineage can be captured at several granularities (system, dataset, column) and in two flavours:

  • Design lineage: intended flows derived from mappings and models.
  • Runtime (operational) lineage: flows actually executed, captured from job execution.

It supports impact analysis (see Architecture Change Process Architect), root-cause analysis of Data Quality issues, regulatory traceability and migration reconciliation.

Distinctions

  • Lineage vs provenance: provenance emphasises the origin and history of a specific data item; lineage emphasises flows between assets. Usage overlaps.
  • Lineage vs knowledge traceability (this knowledge base's source → decision → implementation chain): same idea applied to architecture knowledge instead of data.

Examples

  • Report KPI "claims ratio" ← mart table ← warehouse fact ← two source systems, with transformation rules on each hop.
