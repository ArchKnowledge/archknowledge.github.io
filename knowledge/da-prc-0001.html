Knowledge Change Review Process

The pull-request based process by which a proposed change to the knowledge graph is validated, reviewed, decided per governance level, recorded, merged and published.

Draft knowledge. Status proposed, quality draft. Not yet reviewed or approved by a human architect.

Purpose

Turn "a proposed change to the governed architecture knowledge graph" (a pull request) into an audited decision. Machine-readable: 00-system/governance/review-process.yaml.

Trigger

A pull request from a feature/, fix/, schema/, taxonomy/ or governance/ branch.

Steps

  1. Submit — contributor opens the PR with the template; discloses AI assistance.
  2. Validate — workflows validate-schema, validate-knowledge, validate-links, governance-check; report in the job summary.
  3. Triage — domain owner assigns a reviewer, confirms required governance levels.
  4. Content review — reviewer applies the Knowledge Quality Model.
  5. Level decisions — semantic → information model → data architecture → technical (Decision Rights Model Architect).
  6. Record — governance record added in the same PR.
  7. Merge — after code-owner review and green checks.
  8. Publish — release tag and publication record.

Inputs

Pull request, validation report, governance levels required.

Outputs

Merged change, governance record, audit trail.

Roles

Contributor, reviewer, domain owner, approvers per level, code owners, publisher — see 00-system/governance/roles.yaml.
