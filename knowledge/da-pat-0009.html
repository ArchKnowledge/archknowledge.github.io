Pattern · Data Platforms

Layered Data Refinement

Organise an analytical platform in successive layers — raw, conformed, consumption-ready — each with explicit quality, modeling and governance guarantees.

Draft knowledge. Status proposed, quality draft. Not yet reviewed or approved by a human architect.

Problem

Analytical platforms mix raw and curated data, so consumers cannot tell what is trustworthy and pipelines become entangled.

Context

Data lakes, lakehouses and warehouses serving several consumers.

Forces

  • Keep raw data for replay/audit vs. offer curated, governed data.
  • Number of layers vs. latency and cost.

Solution

Define layers with contracts:

Layer Also called Content Guarantee
Raw bronze, landing source data as received, append-only completeness of receipt, lineage
Conformed silver, integrated cleansed, integrated, historized, linked to concepts quality rules passed, semantics mapped
Consumption gold, marts purpose-built models (e.g. dimensional) fit for a specific use, owned

Promotion between layers passes a Data Quality Gate.

Architecture

Sources → Raw → [gate] → Conformed → [gate] → Consumption → BI / ML / APIs

Advantages

  • Replayability; clear trust levels; separation of concerns.

Disadvantages

  • Data duplication; added latency.

Risks

  • Layers named but without guarantees ("gold" that nobody owns).
  • Semantic integration postponed indefinitely in the conformed layer.

When to Use

  • Multi-source, multi-consumer analytical platforms.

When Not to Use

  • Single-source operational reporting; virtualization suffices.

Alternatives

Classic staging–warehouse–mart; Data Virtualization.

Examples

  • Claims data landed raw hourly, conformed with a bitemporal policy model, served as a claims mart.
