Pattern · Data Migration

Big Bang Data Migration

Migrate all data in a single cut-over event after rehearsals, switching all users from source to target at once.

Draft knowledge. Status proposed, quality draft. Not yet reviewed or approved by a human architect.

Problem

Data must move to a new system, and coexistence is impractical.

Context

Moderate volumes, tightly coupled data, acceptable downtime window.

Forces

  • Simplicity vs. concentrated risk.

Solution

Build and rehearse the full migration repeatedly (dress rehearsals with production copies), reconcile each rehearsal, then execute once in a planned window with a go/no-go decision and rollback plan.

Architecture

Freeze → extract → transform → load → reconcile → go/no-go → switch (or rollback)

Advantages

  • No coexistence; simpler design; shorter total duration.

Disadvantages

  • All risk concentrated in one event.

Risks

  • Downtime overrun; rollback infeasible after go-live transactions.

When to Use

  • Data cannot be partitioned; downtime acceptable; rehearsals feasible.

When Not to Use

  • Mission-critical systems without downtime tolerance.

Alternatives

Phased Data Migration.

Examples

  • Weekend cut-over of an HR system after three rehearsals.
