Knowledge Base Maturity Model

Five-level maturity model for an architecture knowledge base, from fragmented to executable, with observable indicators and automatable checks per level.

Draft knowledge. Status proposed, quality draft. Not yet reviewed or approved by a human architect.

Purpose

Assess and steer the maturity of this (or any) architecture knowledge base (spec §18). Target: Level 5.

Scope

The knowledge base as a whole, or a single domain within it.

Structure

Level Name Description Observable indicators Automatable check
1 Fragmented Knowledge exists but is mostly unstructured. documents, notes, no IDs —
2 Documented Knowledge is documented and categorized. domain folders; titles; some metadata % objects with type and domain
3 Structured Knowledge objects and relationships are explicit. schemas; typed relationships; resolved links zero E0xx errors; relationships per object ≥ 2; few orphans
4 Governed Ownership, validation and lifecycle management. owners/reviewers assigned; lifecycle transitions enforced in CI; approvals recorded % objects ≥ validated with owner; CI transition check active
5 Executable Knowledge drives decisions, assessments, validation and automation. decision trees and assessments used in practice; products generated from graph; validation of real architectures against knowledge exports consumed by tools; assessments derived from objects

Scoring Mechanism

Ordinal per domain: the highest level whose indicators are all met. No averaging across domains — report per domain.

Interpretation

Release 0.1 of this repository is expected to reach Level 3 (Structured) structurally, with Level 4 mechanisms in place (lifecycle, owner checks, CI) but not yet exercised: no object has passed human review, so it cannot claim Level 4.

Recommended Actions

  • 2 → 3: introduce schemas and typed relationships; run the validator.
  • 3 → 4: assign owners and reviewers; move objects through review; enforce --base transition checks in CI.
  • 4 → 5: use decision trees and assessments in real engagements; generate products (checklists, guides) from the graph; feed exports into tooling.
