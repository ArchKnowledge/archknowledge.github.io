Apache Iceberg

Open table format for large analytic datasets providing snapshots, time travel, schema evolution and hidden partitioning on file/object storage.

Draft knowledge. Status proposed, quality draft. Not yet reviewed or approved by a human architect.

Purpose

Reliable, engine-independent tables on object storage for lakehouse architectures.

Capabilities

  • Snapshot-based commits with atomic table changes.
  • Time travel to prior snapshots (technical, transaction-time-like).
  • Schema evolution and partition evolution; hidden partitioning.
  • Access from multiple processing engines via catalogs.

Limitations

  • Snapshot time travel is bounded by snapshot expiration and is not a business history model (no valid time).
  • Requires a catalog and maintenance (compaction, snapshot expiry).

Architecture Role

Storage/table layer of a Data Platform; physical layer of Layered Data Refinement.

Applicable Patterns

Layered Data Refinement, Change Data Capture targets, Slowly Changing Dimension Type 2 tables.

Alternatives

Other open table formats; warehouse-native storage.

Integration

Engines and catalogs vary; verify per environment.

Verification Notes

No version pinned; capabilities stated at a general level.
