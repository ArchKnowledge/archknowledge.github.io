Decision · Foundations

Use Markdown and Git as the Initial Knowledge Store

Implement the knowledge graph initially as Markdown files with YAML front matter in a Git repository, navigable in Obsidian, validated by a script.

Draft knowledge. Status proposed, quality draft. Not yet reviewed or approved by a human architect.

Context

The knowledge base must be personally usable now, governed, and transformable later into another knowledge-store technology (spec §19, §38).

Problem

Which storage and change-management mechanism to use for version 0.1?

Options

  1. Markdown + YAML front matter + Git (+ Obsidian as viewer).
  2. A graph database (property graph or RDF triple store) from the start.
  3. A wiki or document-management system.

Evaluation Criteria

Human readability, machine readability, change governance, tooling cost, portability, graph navigation.

Trade-offs

Option Gains Losses
Markdown + Git readable, diffable, PR-based governance, free, portable no query language, validation must be built
Graph database queries, constraints lower readability, no PR review, lock-in early
Wiki easy editing weak structure and validation

Decision

Proposed: option 1. Typed relationships live in front matter so the files can be exported to a graph (dakb.py export produces JSON, CSV and RDF Turtle).

Consequences

  • Validation is implemented as a script and CI workflow.
  • Query capability is limited until export targets are used.

Assumptions

  • Repository stays below a few thousand objects for the Markdown phase.

Constraints

  • Must open in Obsidian (spec §38).
