Architecture Decision Framework

A structured, machine-readable sequence for taking architecture decisions - question, criteria, conditions, alternatives, consequences, decision, evidence - that links each stage to knowledge objects.

Draft knowledge. Status proposed, quality draft. Not yet reviewed or approved by a human architect.

Purpose

Make architecture decisions reproducible and machine-supported: every stage has a defined output that is itself structured knowledge, so decision support does not live only in prose or in AI prompts.

Structure

  1. Question — What must be decided, at which architecture layer? (output: problem statement and layer)
  2. Decision criteria — Which criteria matter, and how much? (output: weighted criteria (scoring model))
  3. Conditions — Which facts about the situation hold? (output: decision facts (decision-facts.yaml))
  4. Possible alternatives — Which options apply under these conditions? (output: options from decision trees and recommendation rules)
  5. Consequences — What does each option imply, including risks and costs? (output: trade-offs from pattern objects)
  6. Decision — Which option is chosen, by whom, with which rationale? (output: architecture decision record)
  7. Evidence — What supports the decision and its approval? (output: evidence and governance record)

How to Apply

  1. State the question and its layer; check that the decision belongs there (Decisions Belong to Their Layer).
  2. Establish the facts (conditions) using the controlled vocabulary in 00-system/taxonomy/decision-facts.yaml.
  3. Generate alternatives: run the relevant decision tree (dakb.py decide, e.g. Database History Pattern Decision Tree) and recommendation rules (dakb.py recommend).
  4. Compare alternatives with a scoring model where one exists (dakb.py score, e.g. History Strategy Scoring Model Professional), adjusting weights to the context.
  5. Record the decision as an architecture decision (template: 00-system/templates/ADR Template.md) linking the options, criteria and principles.
  6. Attach evidence and take the decision through governance (Separate Decision per Governance Level).

Limitations

The framework structures a decision; it does not take it. Scores and rules are expert judgement with declared confidence, not optimisation.
