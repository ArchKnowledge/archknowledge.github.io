Concept · Data Modeling

Information Model

A paradigm-independent model that represents governed meaning as information structures — classes, attributes, relationships, cardinalities and information-level constraints including history requirements.

Draft knowledge. Status proposed, quality draft. Not yet reviewed or approved by a human architect.

Definition

An Information Model represents governed meaning as information structures — classes, attributes, relationships, cardinalities and information-level constraints (including history requirements) — independent of any data paradigm or technology.

Explanation

The information model answers: how is the meaning defined in the Semantic Model represented in an information model? It is typically expressed in UML class diagrams or an equivalent notation. It is the layer at which information-level history requirements (valid time, transaction time) are stated, before a technical mechanism is chosen.

Distinctions

  • Versus Semantic Model: the semantic model defines meaning (e.g. "a Customer is a Party with an active Agreement"); the information model represents it ("Customer: attribute customerSince 1..1").
  • Versus Logical Data Model: the information model is paradigm-independent; the logical model commits to relational, dimensional, graph or document structures.
  • Some frameworks use "information model" and "logical data model" as synonyms. This knowledge base does not — flagged as interpretation.

Examples

  • A UML class model of Party, Role, Agreement with multiplicities and a note "Agreement must be reconstructable as known at any past date".

Open Questions

  • Needs validation whether the separation from the logical data model is useful for all target audiences.
