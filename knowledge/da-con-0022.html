Concept · Data Quality

Data Quality Dimension

A named aspect of data quality — such as completeness, accuracy, consistency, timeliness, validity or uniqueness — along which quality requirements are specified and measured.

Draft knowledge. Status proposed, quality draft. Not yet reviewed or approved by a human architect.

Definition

A Data Quality Dimension is a named aspect of data quality along which requirements are specified and measured.

Explanation

Commonly used dimensions (lists differ between sources; this is common practice, not a single standard):

Dimension Question
Completeness Are required values present?
Validity Do values conform to the defined domain/format?
Accuracy Do values correctly represent reality?
Consistency Do related values agree across records and systems?
Timeliness Is data available and current when needed?
Uniqueness Is each real-world entity represented once?

ISO IEC 25012 Data Quality Model defines its own set of characteristics (inherent and system-dependent); names and definitions differ from the list above. Mapping between the two is an open task.

Distinctions

  • A dimension is not a rule: rules are concrete, testable checks that measure a dimension.

Examples

  • Rule "email matches pattern" measures validity; "customer has exactly one active record" measures uniqueness.

Open Questions

  • Map the common-practice dimensions to the ISO/IEC 25012 characteristics after verification against the standard text.
