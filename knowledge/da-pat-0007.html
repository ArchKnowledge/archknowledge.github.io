Pattern · Data Integration

Data Virtualization

Provide an integrated, queryable view over multiple sources at query time without physically copying the data.

Draft knowledge. Status proposed, quality draft. Not yet reviewed or approved by a human architect.

Problem

Consumers need a combined view of data from several systems, but copying is undesirable (latency, duplication, privacy).

Context

Exploratory analytics, low-volume operational lookups, regulated data that must stay in place.

Forces

  • Freshness and no duplication vs. performance and source load.

Solution

A virtualization layer exposes logical views that are translated at query time into queries on the underlying sources, with optional caching.

Architecture

Consumer → virtual view layer (semantic mapping, security) → source A / source B / source C

Advantages

  • Current data; no copies to govern.
  • Fast to set up for prototypes.

Disadvantages

  • Performance depends on sources; complex joins across sources are slow.
  • No history unless sources keep it.

Risks

  • Operational sources overloaded by analytical queries.

When to Use

  • Low volume, high freshness, data must not be copied.

When Not to Use

  • Heavy analytics or history requirements → Batch Extract-Transform-Load into a platform.

Alternatives

Batch Extract-Transform-Load, Change Data Capture.

Examples

  • A combined customer view for a service desk over CRM and billing.
