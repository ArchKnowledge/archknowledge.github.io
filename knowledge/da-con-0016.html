Concept · Metadata Management

Metadata

Data that describes other data or data-related assets — their meaning, structure, origin, quality, ownership, usage, security and processing.

Draft knowledge. Status proposed, quality draft. Not yet reviewed or approved by a human architect.

Definition

Metadata is data that describes other data or data-related assets — their meaning, structure, origin, quality, ownership, usage, security and processing.

Explanation

This knowledge base distinguishes nine metadata categories (spec §9). The categories overlap; a single attribute may serve several.

Category Describes Examples Typical owner
Business meaning and business context definitions, business rules, owner Data Owner / Data Steward
Technical structure and storage schemas, data types, keys Data Custodian
Operational runtime behaviour load times, row counts, job status platform operations
Process processes that create/use data producing process, SLA process owner
Semantic meaning formally concept links, ontology IRIs Semantic Architect
Governance decisions and accountability status, approvals, policies Data Steward
Quality fitness for use DQ rules, scores Data Steward
Security protection classification, access policies Security Architect
Lineage origin and flow source-to-target mappings Data Architect

Architectural concerns: metadata ownership, lifecycle (metadata also goes through draft → approved → deprecated), standards (ISO IEC 11179 Metadata Registries), quality, repositories and APIs, and automation (Metadata Harvesting). See Metadata Management Reference Architecture Architect.

Distinctions

  • Metadata vs Reference Data: reference data are values used in business data; metadata describes data.
  • The distinction is role-based, not intrinsic: a data dictionary is data to its own maintenance system.

Examples

  • A column's business definition, its classification "confidential" and its lineage from a source system.
