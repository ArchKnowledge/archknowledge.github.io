Data Architecture

The discipline and resulting structures that define how an organisation's data is described, organised, integrated, governed and realized across systems, from business meaning to technical implementation.

Draft knowledge. Status proposed, quality draft. Not yet reviewed or approved by a human architect.

Definition

Data Architecture is the discipline and the resulting set of structures that define how an organisation's data is described, organised, integrated, governed and realized across systems — from business meaning down to technical implementation.

Explanation

Data Architecture spans the whole Architecture Layer stack. It is not a single model or a single platform; it is the coherent set of decisions that determine:

  • which data exists and what it means (in cooperation with semantic and information architecture);
  • how data is structured (data models at conceptual, logical and physical level);
  • where data is authoritative and how it moves (Data Integration, Each Data Element Has an Authoritative Source);
  • how data is stored and processed (Data Platform);
  • how data changes over time (Data Lifecycle, Temporal Data Management);
  • how all of this is governed (Data Governance, Architecture Governance Model).

Its outputs are models, principles, standards, patterns, architecture decisions and reference architectures.

Distinctions

  • Not the same as Information Architecture: information architecture focuses on the structure and meaning of information as used by people and processes; data architecture additionally covers realization, integration, platforms and operations. The boundary is contested (see Open Questions).
  • Not the same as a Data Platform: a platform is one realization component of the architecture.
  • Not the same as data modeling (Data Model): modeling is one of the core activities within data architecture.

Examples

  • Defining that customer data is authoritative in one system and replicated elsewhere via Change Data Capture.
  • Deciding that historical data must be reconstructable for seven years, and choosing a Bitemporal Data Model to realize that.

Open Questions

  • The boundary between data architecture and information architecture differs between frameworks. This knowledge base treats them as overlapping disciplines with different emphasis; the interpretation is expert-interpretation and awaits review.
