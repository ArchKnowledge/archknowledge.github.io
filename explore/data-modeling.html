Data Modeling

Conceptual, information, logical and physical data modeling; temporal modeling.

13 objects. Linked titles are published on this site; titles marked Professional or Architect belong to planned commercial tiers. Repository folder: 03-data-modeling

Concepts 6

  • Conceptual Data ModelA data model that identifies the business things of interest and their high-level relationships, without attributes' technical detail and independent of any implementation.
  • Data ModelA structured representation of data — its entities, attributes, relationships and constraints — at a stated level of abstraction and for a stated purpose.
  • Information ModelA paradigm-independent model that represents governed meaning as information structures — classes, attributes, relationships, cardinalities and information-level constraints includ
  • Logical Data ModelA data model that structures information in a chosen data paradigm (e.g. relational, dimensional, graph, document) with keys, relationships and constraints, independent of a specif
  • Physical Data ModelA data model that specifies how a logical data model is realized in a specific data store, including data types, storage structures, indexing, partitioning and physical history mec
  • Temporal Data ManagementThe capture, storage and querying of how data and knowledge about data change over time, including valid time (when a fact is true in reality) and transaction time (when the fact w

Patterns 3

  • Bitemporal Data ModelRecord both valid time and transaction time for each fact so that any past state can be reconstructed as it was true and as it was known.
  • Event SourcingPersist every state change as an immutable domain event in an append-only log and derive current and past states by replaying events.
  • System-Versioned History TableLet the database automatically keep every prior version of a row, with system-maintained transaction-time periods, in an associated history table.

Anti-patterns 2

  • Overloaded AttributeOne attribute carries different meanings depending on context, record type or time, instead of separate, well-defined attributes.
  • Physical-Model-First DesignData structures are designed directly as database tables, skipping the conceptual, semantic and information layers.
