Architecture Patterns

Patterns and anti-patterns.

22 objects. Linked titles are published on this site; titles marked Professional or Architect belong to planned commercial tiers. Repository folder: 19-architecture-patterns

Patterns 16

  • Batch Extract-Transform-LoadPeriodically extract data sets from sources, transform them and load them into a target, in scheduled batches (ETL or ELT).
  • Big Bang Data MigrationMigrate all data in a single cut-over event after rehearsals, switching all users from source to target at once.
  • Bitemporal Data ModelRecord both valid time and transaction time for each fact so that any past state can be reconstructed as it was true and as it was known.
  • Change Data CaptureDetect inserts, updates and deletes in a source database (typically from its transaction log) and propagate them as a change stream to targets.
  • Concept-to-Model TraceabilityLink every model element at each layer to the governed concept it represents and to the model element it realizes, so meaning and impact can be traced across layers.
  • Data ContractMake the interface between a data producer and its consumers an explicit, versioned, owned agreement covering schema, semantics, quality and service levels, and enforce it automati
  • Data Quality GateValidate data against explicit quality rules at defined points in a data flow and block, quarantine or flag data that fails, with evidence recorded.
  • Data VirtualizationProvide an integrated, queryable view over multiple sources at query time without physically copying the data.
  • Event SourcingPersist every state change as an immutable domain event in an append-only log and derive current and past states by replaying events.
  • Layered Data RefinementOrganise an analytical platform in successive layers — raw, conformed, consumption-ready — each with explicit quality, modeling and governance guarantees.
  • Master Data HubManage shared master data entities in a hub that performs identity resolution, maintains golden records and cross-references, and distributes master data, in registry, consolidatio
  • Metadata HarvestingAutomatically extract technical, operational and lineage metadata from source systems, pipelines and tools into a central metadata repository on a schedule or event basis.
  • Phased Data MigrationMigrate data in successive waves (by product, region or entity), with source and target coexisting and synchronised during the transition.
  • Reference Data HubMaintain code lists centrally with versions, validity periods and cross-list mappings, and distribute them to consuming systems.
  • Slowly Changing Dimension Type 2In a dimensional model, preserve history of dimension attributes by inserting a new dimension row with its own surrogate key and effective period for each change.
  • System-Versioned History TableLet the database automatically keep every prior version of a row, with system-maintained transaction-time periods, in an associated history table.

Anti-patterns 6

  • Governance as AfterthoughtGovernance is applied as a documentation and approval step at the end of delivery, instead of being embedded in the architecture and workflow.
  • Implicit SemanticsThe meaning of data exists only implicitly in column names, application code or people's heads, instead of in governed definitions.
  • Migration Without Data ProfilingMigration mappings are designed from documentation and schema only, without profiling the actual source data.
  • Overloaded AttributeOne attribute carries different meanings depending on context, record type or time, instead of separate, well-defined attributes.
  • Physical-Model-First DesignData structures are designed directly as database tables, skipping the conceptual, semantic and information layers.
  • Point-to-Point Integration SprawlSystems are integrated through many individually built point-to-point interfaces, each with its own mapping, semantics and quality handling.
